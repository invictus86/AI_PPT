# 交付文件命名规范

> 当前1.2.0：三步基础流程见《阶段流程.md》。第一步规划经主控深度审阅可生成四封面，用户选封面并授权试做时才确认规划；第三步实际全稿由主控验收锁定，不新增PDF用户审批。主题活动内容与配套优先遵循《主题班会与家长会深度二创规范.md》《主题活动教案与会议实施方案规范.md》。

## 命名目标

阶段2、阶段3和阶段4的用户可交付文件必须能从文件名看出主题和类型，避免多个项目都叫 `图片版PPT.pdf`、`逐字稿.docx` 或 `<班会教案或会议实施方案>.pdf`。

## 主题来源

交付文件名前缀取“封面第一页上的主题”。主控在阶段1必须把这个主题稳定写入：

- `_state/阶段1/content.json` 的 `deck_title`。
- 第 1 页或封面页的最终可见主标题，通常是 `slides[0].final_visible_text[0]`。
- `页面规划.md` 和 `每页干净逐字稿.md` 中第 1 页对应的封面主标题。

如果封面页的页面标题只是“封面”“首页”“标题页”等泛化名称，不得拿它当文件名前缀；应使用封面可见主标题或 `deck_title`。如果阶段1内容资产暂不可用，runtime 可以用项目名兜底，但主控交付前应按封面主题修正。

## 项目目录编号

编号用于外层输出项目目录，来源与格式按[项目目录规范](项目目录规范.md)执行。阶段2、阶段3交付文件名前缀和阶段4主题子目录仍使用封面主题，不从项目目录自动添加编号。例如项目 `17-公共场所防踩踏小学主题班会/` 的PDF命名为 `公共场所防踩踏｜图片版PPT.pdf`。

阶段1内容暂不可用而用项目名兜底时，去掉项目名中的管理编号。封面主题本身经批准含有数字时保持原文；不因目录管理需求改动 `deck_title`、页面可见文字或逐字稿正文。已有交付物不因本次目录重命名而自动改名。

## 标准文件名

`<命名前缀>` 等于封面第一页主题，不自动附加项目目录编号。

阶段2图片版 PDF：

```text
阶段2_图片版PPT/pdf/<命名前缀>｜图片版PPT.pdf
```

阶段3逐字稿：

```text
阶段3_逐字稿与教案输出/逐字稿/<命名前缀>｜逐字稿.md
阶段3_逐字稿与教案输出/逐字稿/<命名前缀>｜逐字稿.docx
阶段3_逐字稿与教案输出/逐字稿/<命名前缀>｜逐字稿.pdf
```

阶段3 K12 教案设计：

```text
阶段3_逐字稿与教案输出/教案设计/<命名前缀>｜教案设计.md
阶段3_逐字稿与教案输出/教案设计/<命名前缀>｜<班会教案或会议实施方案>.docx
阶段3_逐字稿与教案输出/教案设计/<命名前缀>｜<班会教案或会议实施方案>.pdf
```

阶段4文件整理主题文件夹中的交付副本：

```text
阶段4_文件整理交付/<命名前缀>/每页干净逐字稿.md
阶段4_文件整理交付/<命名前缀>/图片素材/slide_001.png
阶段4_文件整理交付/<命名前缀>/逐字稿图片/page_001.png
阶段4_文件整理交付/<命名前缀>/<命名前缀>｜图片版PPT.pdf
阶段4_文件整理交付/<命名前缀>/<命名前缀>｜逐字稿.docx
阶段4_文件整理交付/<命名前缀>/<命名前缀>｜逐字稿.pdf
```

K12 项目且阶段3教案 DOCX/PDF 已存在时，主题文件夹中额外纳入：

```text
阶段4_文件整理交付/<命名前缀>/教案设计图片/page_001.png
阶段4_文件整理交付/<命名前缀>/<命名前缀>｜<班会教案或会议实施方案>.docx
阶段4_文件整理交付/<命名前缀>/<命名前缀>｜<班会教案或会议实施方案>.pdf
```

主题文件夹直接位于 `阶段4_文件整理交付/` 下，不再放在项目根部，也不再额外套 `最终交付/`。阶段3逐字稿 Markdown、教案 Markdown 和各类说明文件不进入阶段4主题文件夹。`逐字稿图片/` 只在逐字稿 PDF 存在且渲染成功时创建；`教案设计图片/` 只在 K12 教案 PDF 存在且渲染成功时创建。两个图片目录只放由同目录 PDF 确定性渲染出的 `216 DPI / 3x_72dpi` PNG，文件名固定为 `page_001.png`、`page_002.png`。

阶段4标准整理结构不包含历史编辑稿。外部编辑稿如需保留，必须作为用户额外要求处理，不进入默认主题文件夹。

## 清理规则

文件名前缀要保留批准的中文主题本身，但必须清理会破坏文件路径或造成歧义的字符：

- 把 `/ \ : * ? " < > |`、控制字符和换行替换为空格。
- 把全角分隔符 `｜` 从主题里移除，分隔符只由命名模板添加一次。
- 合并连续空格，去掉首尾空格、点号、下划线和横线。
- 主题过长时可以截短到可读范围，保留能识别项目主题的前半部分。

## 旧资料的使用边界

不恢复旧项目状态，不搜索旧固定名或旧阶段4演讲稿目录作为交付回退。只从当前项目manifest、state实际记录和当前主题命名路径核对产物。

旧项目历史编辑稿仅可作为新项目登记的源资料，不是新阶段模型的标准交付文件。新生成、新入账和新交付一律使用主题化命名。manifest、`project_state.user_artifacts`、`project_state.expected_user_paths` 和主控决策中的 `confirmed_files` 必须记录真实路径，不要继续写旧固定名。
