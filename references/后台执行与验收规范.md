# 后台执行与验收 · 1.3.1

本规范适用于全部资料整理、制作、配套、预览与教学动画步骤。用户要求全程后台；不得前台打开Office/WPS、启动放映、设置Visible=true、激活窗口、截图桌面或使用键鼠。后台失败时报告真实缺口，禁止临时改走前台。后台调用PowerPoint进程仍需要本机软件；这不等于完全不依赖Office。

## 工具分工

- 文字、对象、页序、媒体、备注和动画：ZIP/XML、python-pptx、lxml直接读取。
- 内容、图片识别和视觉审阅：主控实际查看后台页面和媒体图片，必要时OCR。脚本不得用关键词猜答案后自动通过。
- 生图、图片PDF、配套Word/PDF：原API及文件库路径；Word/PDF实际审阅保持，禁止前台应用备用路线。DOCX与独立生成PDF不天然代表相同分页，不能据后者宣称前者页面布局完全一致。
- 阶段0一体入口：`extract-ppt-background --input-pptx <绝对路径> --output-dir <项目_state内绝对目录>`提取真实页序、嵌套文字、备注和原媒体，并后台渲染全部页。按输入指纹建子目录；不会自动宣布内容完整，仍需主控看图/OCR。
- PPTX后台预览：`render-ppt-background --input-pptx <绝对路径> --output-dir <项目_state内绝对目录>`。动画项目使用`export-animation-previews --run-dir <项目>`。隐藏文稿窗口、后台Slide.Export、临时加载可支持嵌入字体，不创建放映窗口。渲染写明来源和字体加载情况；未安装/未支持字体或显示异常必须明确处理，不能换字体制造正常截图。
- 动画写入：直接写入OOXML，只允许计划页`p:timing`以及另行授权的整句字体/粗体清单。源文件和其余包内容保持。
- 点击状态：读取最终PPTX时间树，建立每次点击完成后可见对象集合，在系统临时副本隐藏未出现对象、去掉时间轴，用同一后台渲染器输出完整画面。临时副本可变换，正式成品不受影响。不是把已渲染的图片涂白，也不是读取计划后假设执行成功。

后台渲染需Windows、PowerPoint、PowerShell以及Pillow、lxml、python-pptx、fontTools。共用office-background队列并保留同Windows登录会话内命名互斥锁串行调用；排队与执行超时分开；后台文稿只读打开，正常与异常结束均执行临时字体清理。嵌入字体的声明名称与内部字体名称不一致时，只在临时副本使用唯一字体别名；仅变更临时字体名称表，原字形和度量保持，正式文件不改字体。记录渲染前后文稿窗口数与实际导出页数；窗口数变化或导出缺页即阻断。缺少验证平台或依赖时记录`verification_skipped`并跳过对应检查，允许其他文件/API步骤继续，不安装或调用前台工具；实际执行错误仍阻断受影响项。旧`.ppt`不以PPTX解析，应报告格式不支持，不能悄悄前台转换。

## 支持范围与质量门槛

DOCX实际排版与PDF全页检查使用《文档后台全页验收规范》的新入口，与PowerPoint共用office-background队列。WPS当前没有经验证的后台适配器，不启用COM别名或前台备用。原PPTX预览缓存绑定源、实现、字体/Office环境及全页图SHA；任何变化重新渲染和审阅。Office超时/执行进程中断时阻断该资源，实际核对任务清理后再恢复。

当前解析器仅接受完整顶层对象0.2—1.2秒淡入，触发为`click`或`with_previous`；同组同步、每组明确单击。已有相同完整对象淡入可以保留或明确替换。对时间树逐节点及结构校验，未知条件、自动开始、after_previous、退出/运动路径、分段文字、复杂交互、音视频、OLE等不近似，不进入完成状态；主控可在授权边界内将教学方案调整为支持的淡入或静态，否则列明阻断页。

检查范围是初始及每次点击完成状态、语义顺序和原包保真。没有验证动画过渡每一帧，没有实际测试任意版本PowerPoint/WPS播放兼容，不能声称“目标播放器实际放映通过”或“所有效果保证完全一致”。环境具备时，在声明支持范围内所有下列门槛必须通过，不为了全程后台删掉视觉QA；缺环境的检查按后文记录未验证，文件差异和时间轴结构核验始终执行：

1. 实际原稿后台全页预览审阅；图中文字与底图残留必须检查，XML不足以覆盖。
2. 明确识别题目、答案、解释与插画。每页plan设`content_roles_reviewed=true`及`visibility_rules`，例如`{"shape_id":7,"role":"answer","reveal_click":2,"reason":"先讨论，再揭示结论"}`。`reveal_click=0`表示初始可见，仅题目/比较素材等适用；答案不得初始可见。没有相关对象时规则为空，但主控仍需确认该页语义及图片里没有需要隐藏的答案。
3. `apply-teaching-animation`执行后核验完整包差异；读取成品时间树核对目标、触发、时长、分组和可见性规则。文件变化或不支持行为即失败。
4. `export-animation-states`导出每页初始、全部点击完成状态；每个状态有实际图片、可见/隐藏对象、输入/输出/计划/图片指纹。空白截图、缺失状态和旧证据均不能验收。
5. 主控逐张审阅全部状态，检查题目与答案是否错序、底图是否露出答案/残影、组内图文是否同步、字体是否缺字/回退、断行和遮挡、最终全部内容是否恢复。
6. 用`record-animation-background-review`登记下面契约；runtime只核对完整性、指纹和声明范围，不自动生成pass。若启用字体检查，同一份全部状态审阅包含全页字体/排版，额外生成独立font_review证据，无需再打开应用。

## 后台审阅契约

```json
{
  "method":"background_click_states",
  "controller_reviewed":true,
  "input_sha256":"sha256:...",
  "output_sha256":"sha256:...",
  "plan_sha256":"sha256:...",
  "manifest_sha256":"sha256:...",
  "unresolved_issues":[],
  "states":[{
    "page":1,"step":0,"pass":true,"image_sha256":"sha256:...",
    "visibility_observation":"写实际可见和隐藏内容",
    "answer_leakage_observation":"写题目、答案及底图文字检查结果",
    "background_residue_observation":"写隐藏对象后背景是否完整",
    "font_observation":"写中文、字体、粗细及原字体保留检查结果",
    "layout_observation":"写断行、遮挡和完整显示检查结果"
  }]
}
```

所有page/step恰好覆盖background_manifest的全部状态，不能只登记初始和最终。每页点击数包含保留的已有动画。输入/输出/plan/manifest/状态图任意变化使验收失效。状态为`waiting_background_review`直到全部检查通过，再`completed`；完成摘要写“后台点击状态验收通过”，不伪造实际放映事实。旧放映验收及旧状态不自动迁移。

## 无环境则不验证

先只读运行`verification-capabilities`。PPTX缺少后台验证依赖时，预览和状态导出返回`verified=false`及缺项，不使用前台Office/WPS替代。资料整理继续直接读取页序、对象、媒体和可取得的文字/图片，无法确认的底图文字与视觉项如实列未验证，不冒称XML提取完整。动画可按已读对象、已确认教学内容作结构计划，`preview_review_evidence`写结构依据与未验证范围，不捏造看图；没有实际诊断证据不改字体。无渲染环境且`font_repairs=[]`表示未验证/未改字体，不表示检查后无需修复。

成品仍做原包差异、完整时间轴、触发/组/可见性规则检查；未解决的实际结构或内容问题仍阻断。环境缺失的动画状态为`verification_skipped`、`background_accepted=false`，只完成文件制作交付，不能称后台视觉、字形或播放器验收通过。基础项目保留原完成事实，独立动画项目可收口文件任务。环境恢复后先导出并实际审阅原稿预览，再重新登记当前计划、执行和导出状态，完整审阅；原未验证成品保留，重新生成按原规则递增版本，不冒充已验证或覆盖旧文件。执行失败、缺页、不支持效果和已发现问题不得用缺环境规则跳过。
