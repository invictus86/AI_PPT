# 项目目录规范

> 当前1.2.0：三步基础流程见《阶段流程.md》。第一步规划经主控深度审阅可生成四封面，用户选封面并授权试做时才确认规划；第三步实际全稿由主控验收锁定，不新增PDF用户审批。主题活动内容与配套优先遵循《主题班会与家长会深度二创规范.md》《主题活动教案与会议实施方案规范.md》。

本文件只规定项目目录、用户可见目录和 `_state/` 内部目录边界。阶段1/2 的风格、提示词和证据链规则按专题 reference 执行。

## 核心原则

每个 PPT 项目必须有清晰的中文阶段目录。阶段目录给用户和主控大模型看，运行过程文件和主控决策集中放到 `_state/`；其中主控决策放到 `_state/decisions/`。

工作区根目录的 `输入资料/` 是用户源文件入口。通过 `add-material` 登记文件资料时，必须在 `输入资料/<项目名>/` 保留一份入口副本；具体项目 `_state/阶段0/原始资料/` 同时保留项目归档副本，供材料索引、提取和后续阶段稳定追溯使用。

## 用户可见目录

- `阶段0_资料整理/`：只放资料清单和资料摘要。资料摘要可以包含主控大模型维护的初步资料理解和缺口，但不能包含正式页面规划。
- `阶段1_规划确认/`：只放真实规划类 Markdown。`页面规划.md` 是权威逐页规划表；`每页干净逐字稿.md` 是用户阅读每页最终可见文字的干净审阅稿；`PPT一致性.md` 承载标题、模块页、页码、logo、公共元素和例外；`图片风格.md` 承载画面风格、参考依据和逐页图片规划。
- `阶段2_图片版PPT/封面风格候选/`：只放四张封面候选图。
- `阶段2_图片版PPT/img/`：试样、全量共用的当前页面图片目录；文件存在不代表通过确认，正式全套以有效结果记录为准；选中且质量通过的封面候选转正后会复制为对应 `slide_XXX.png`。
- `阶段2_图片版PPT/pdf/`：只放由阶段2正式页面图打包出的图片版 PDF，新生成文件命名为 `<封面第一页主题>｜图片版PPT.pdf`。
- `阶段3_逐字稿与教案输出/逐字稿/`：放逐字稿 Markdown、Word 和 PDF，新生成文件命名为 `<封面第一页主题>｜逐字稿.md/docx/pdf`，不再嵌套 `docx/` 或 `pdf/` 子目录。
- `阶段3_逐字稿与教案输出/教案设计/`：两种主题场景均输出，内部目录名不影响成品名称；按scene命名 `<封面第一页主题>｜班会教案.md/docx/pdf` 或 `<封面第一页主题>｜会议实施方案.md/docx/pdf`。
- `阶段4_文件整理交付/<主题名称>/`：阶段4创建或刷新，放交付整理副本；不放 `_state`、封面候选、试样图、说明类文件、逐字稿 Markdown 或教案 Markdown。识别实际产物复制并核对指纹；PDF实际渲染成功后才导出 `216 DPI / 3x_72dpi` 图片。没有配套或母版会阻止完成；不创建占位文件或空图片目录。阶段4不检查或等待PPTX，复制和渲染不代表质量验收或阶段完成。

动画不创建`阶段5_PPT教学动画/`或其他用户可见的阶段5交付文件夹。成品`<原名>_可编辑动画版.pptx`直接放输入PPTX同目录，同名递增版本；后台预览、计划、差异及全部点击状态与审阅证据保存在项目内部`_state/阶段5/`。独立动画状态不撤销阶段4完成。只做已有PPTX动画的项目以`init --animation-only`创建，不建立阶段0—4或阶段5交付目录。实际存放规则见《阶段5PPT教学动画规范.md》。

## 运行过程目录

以下内容全部放 `_state/`：

- JSON 状态文件。
- packet。
- manifest。
- prompt 原稿。
- 日志。
- 校验报告。
- worker 输出。
- 中间 brief。
- 素材索引。
- 提取文本。
- 原始资料归档。注意：这里是项目内部归档副本，不替代工作区根目录 `输入资料/<项目名>/` 中的源资料入口副本。
- 网页资料归档，例如微信公众号文章的 URL、HTML/截图、图片清单、采集说明和 metadata。
- 阶段1 `design_contract.json`、`layout_safety_contract.json`、`content.json`、`slide_prompt_briefs.json`、`slides.json` 等主控资产。
- 阶段2封面候选 style card、packet、prompt、provider 结果、batch 记录和用户选择记录。
- 阶段2B试样 packet、prompt、provider 结果、batch、对应路线 evidence、试样 review 和 promotion 记录。
- 阶段2图片的尺寸策略记录，包括 `target_size=1672x941`、`preferred_minimum_size=1600x900`、实际宽高、目标容差、`meets_target_size`、`meets_preferred_size`、`size_warnings` 和可能的降采样风险记录。
- 阶段2轻量审美 QA 记录。
- 阶段3逐字稿 JSON、manifest、按需调研记录、K12 教案 JSON、manifest、上下文、自审记录和生成日志。
- 阶段4整理 manifest、organize summary、PDF 图片派生记录和日志。
- 阶段外工具任务记录，例如 Canva 辅助编辑任务的 task、导入尝试、设计链接、逐页参考文案、页面审查、批量修改日志和人工待处理项。

主控决策 JSON 全部放 `_state/decisions/`。

## 阶段外工具任务目录

阶段外工具任务可以读取项目资产作为参考，但不属于阶段0到阶段4的正式流程，不改变 `project_state.current_stage`，不替代阶段确认或阶段交付。

Canva 辅助编辑任务记录建议放在：

```text
_state/工具任务/canva/<task_id>/
  task.json
  import_attempt.json             # 设计获取记录，执行器无关
  design_link.json
  reference_text_by_slide.json
  page_audit.json
  batch_edit_log.jsonl
  manual_todos.md
  export_record.json              # 仅实际导出时存在
```

这些记录只用于恢复和审计：

- 不放进阶段3用户目录。
- 不放进 `_state/阶段3/` 作为阶段3完成证据。
- 不作为阶段3逐字稿/教案输出的默认锁定稿依据。
- 不反向覆盖阶段1逐字稿或阶段2确认图。
- `task.json` 记录国际版 Canva provider、host profile、实际 executor 与选择依据；它们不进入 `project_state`。

## 禁止事项

- 不要在阶段目录里放脚本中间文件。
- 不要把 Skill 根目录当作具体 PPT 项目目录。
- 不要把 `_state/project_state.json` 之外的文件当作机器事实源。
- 不要把说明类 Markdown 当作阶段推进依据；阶段事实以 `_state`、manifest 和 decision 为准。
- 不要把封面候选图混进阶段2正式页面图的 `img/` 或阶段3输出目录。
- 不要把试样图直接混进阶段2正式 `img/`，除非用户已经确认试样并由 runtime 记录 promotion。
- 不要让阶段0资料摘要替代阶段1 `页面规划.md`。
- 不要把历史编辑稿或外部编辑稿放入阶段4标准主题文件夹，除非用户明确要求作为额外文件保留。
