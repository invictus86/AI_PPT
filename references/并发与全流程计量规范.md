# 并发、恢复与全流程计量 · 1.3.1

不同项目文件工作可并行。生图保持原Skill的批次独立并发规则；同项目写事务、同Canva设计及后台Office操作单独保护。原三步授权、正文唯一源、用户选封面/试样暂停、Canva5页批次及动画全部状态验收保持。

## 已实现的资源边界

- 项目写入：CLI写命令共用项目锁；state采用revision比较及原子保存。慢预览/点击状态生成完成后，先在项目短锁内核对revision，再发布manifest并保存state及真实文件SHA；另一窗口已更新时旧清单和状态不覆盖；重新resume-brief/drift-check后继续。直接调用runtime写状态同样检查revision；不要绕过CLI手工覆盖state。
- 生图：单个batch/run使用独立线程池，最大并发6，保留原parallel_required=true。多个独立batch或窗口可同时运行，不共享账号并发额度，不设全局生图互斥、账号许可池或共享限流退避。例如3个独立批次各6张，Skill层可同时18个请求；实际仍受中转服务侧限制。限流只记录该请求的技术错误，仍不切路线/模型、不自动重复未知请求。
- 同图：逻辑请求键包含目标、生成依据、完整prompt、实际输入、参数和账号标识；锁限定项目路径与这一请求键，仅防止同项目同一张图被重复提交，不限制其他图、项目或批次。批次同源重派保持已完成结果；已返回但未登记的输出可补登记，不等于视觉QA通过。显式force表示新尝试，不用于普通恢复。依据改变或实际修订生成新请求。
- Canva：每个设计的交易先领取持久租约，覆盖start至commit/cancel。新任务记录无租约不能登记交易；不同设计可并行。同设计其他窗口等待或只读，交易不因CLI退出而自动解锁。
- 后台Office：PowerPoint与Word共用office-background队列；PowerPoint另保留同Windows登录会话内命名Mutex。排队时间与实际渲染超时分开。中断/超时后清理事实不明时阻断Office，不能重开前台或结束用户进程。
- 输出与缓存：实际输出目录排他预留；渲染输出目录也有独立锁。缓存绑定输入SHA、渲染实现、Office文件版本信息、字体环境与实际图SHA；不按文件存在自动复用。字体环境不能可靠识别时使用PPT_SKILL_RENDER_ENV_VERSION标识变化或重新渲染。

共享保护数据在Windows LOCALAPPDATA/ppt-skill-v3/runtime；其他平台为用户缓存目录。PPT_SKILL_RUNTIME_DIR可显式指定目录，操作同项目/Canva设计/Office会话的窗口必须使用同一目录；此目录不用于共享或限制生图账号额度。记录不保存密钥；项目证据仍在项目_state，壳层不增加临时目录。

## 恢复与Canva入口

```bash
python .skill/scripts/pptctl.py resource-status
python .skill/scripts/pptctl.py claim-canva-design --run-dir <项目> --task-id <任务> --design-id <实际设计ID>
```

先claim再启动插件/MCP transaction。正常终态仍由record-canva-task-event核验原逐页审计并登记committed/cancelled，然后释放租约；failed不能证明远端已取消，保留租约直到确认。重新连接使用返回的lease-token恢复同一任务，不能另领租约绕过未保存草稿。不要在日志保存transaction ID或签名链接。

未知图片请求：先看request_results和对应API输出/evidence。存在可恢复图就恢复同批；确实没有返回且已核实后，使用resolve-image-request --request-key <键> --evidence <JSON>，证据含controller_reviewed=true、resolution=confirmed_no_result和具体reason。不能仅因等待时间长判无返回；没有服务幂等/查询能力时不承诺绝无重复费用。

后台Office中断：resource-status读取未收口资源；只核对并清理本任务所属文稿/临时字体。实际确认worker停止且资源清理后，resolve-office-recovery --evidence <JSON>，含controller_reviewed、worker_stopped_confirmed、task_documents_and_fonts_cleared均为true及具体reason。不得杀用户Office/WPS或把前台检查作为恢复步骤。

PPT_SKILL_QUEUE_TIMEOUT默认3600秒，只作用于上述项目/同请求去重/Canva/Office等保护，不设置账号级生图等待。API或Office运行超时单独计算；批次并发参数只作用当前batch/run，并保留同模型/质量。安装/更新Skill前应先收口运行任务，不能在不同窗口运行时替换其共享代码。

## 全流程计量

CLI项目操作自动记录活动跨度；生图记录实际API等待和返回usage，不记录不存在的账号队列耗时。非缓存输入、输出、人工转换/导出等可用以下入口补充真实数据：

```bash
python .skill/scripts/pptctl.py record-measurement --run-dir <项目> --measurement <JSON>
python .skill/scripts/pptctl.py metrics-summary --run-dir <项目>
```

测量字段：source为codex/image_api/manual/runtime；record_id为唯一response/API调用或操作ID；stage、operation必填。可记录turn_id、started_at/completed_at、activity_seconds、queue_seconds、execution_seconds、api_wait_seconds、manual_seconds、input_tokens、cached_input_tokens、output_tokens、total_tokens、usage、status、rework_category、notes、duration_lower_bound；未知字段省略或null。

同source/record_id去重，不把不同值静默相加。缓存包含在输入，推理如已包含在输出不另加；中转Token与Codex、Canva积分分别列账。脚本没有宿主模型response用量时保持缺测，不能用字符数推算；人工转换不能用聊天交接间隔推算耗时。嵌套跨度、并行项目时间和等待时间不可重复加为串行用户耗时。

质量返工、技术失败/损坏补图、需求改版、已合格图非必要重生分开。首次有效图的首次QA通过率按相同内容版本统计，封面/内页分开；用户发现漏判须修正首次通过记录。多原因标签不能相加冒充总返工次数。

## 节约Token而不降低质量

开始/继续仍核查核心规范、阶段流程、恢复协议；同一回合内未变文件不重复回传全文。恢复摘要包含当前runtime版本、state revision和关键源SHA，用它定位变化后再读必要来源。工具结果优先返回差异、计数和证据路径；原尺寸文字和必要视觉图不能被摘要省掉。独立读取可批量，依赖编辑、审批和提交保持顺序。等待由脚本承担，不让主控反复空轮询。

恢复优先resume-brief --compact；有上次保存摘要时加--since <上次JSON>读取changed_files/removed_files。完整原摘要仍可不加--compact读取，所有doctor阻断项保留。metrics-summary默认只输出来源计数与缺测；--detail才返回全部记录，避免把不断增长的账本反复塞进上下文。

缓存复用的是仍有效的证据，不省略首次逐页/逐状态审阅。每张新图和编辑图重查整页；新PPTX或改字体后重新核对对象与所有受影响状态。无多进程容量实测时不承诺固定窗口数；WPS未验证后台适配器，不支持自动替代。

## 明确失败与未知结果分别处理

HTTP明确拒绝（400/401/403/404/405/413/415/422/429）记录`rejected`，保留该次计量，同一模型/路线可以在修正原因后重新请求；429归技术失败，不算视觉返工，不设账号队列/共享退避。每次失败尝试有独立ID，不因同请求重复记录冲突。无法判断是否生成的超时、服务异常或断连仍记`unknown`，禁止盲目重复；已返回损坏图记`returned_unusable`，保留usage并先核对恢复证据。HTTP状态不能独立证明免费或未计费。

Canva failed租约用`resolve-canva-recovery`登记实际原交易cancel/commit收口证据后释放；不修改原失败批次，不以时间到期或虚构新批次解锁。具体合同见Canva规范。
