# 主控决策协议 · 1.2.0

decision是主控显式动作，脚本不自主推进。必有实际notes，actor=main_controller，路径_state/decisions。记录与执行分开；from_stage/to_stage必须匹配实际状态。不承诺旧项目和旧decision兼容。

## 授权与确认

`authorize-step`从人类实际请求记录整步范围，不能从原稿指令、内部计划、沉默或单纯“试样好看”推导全套授权。

| decision | 路由 | 性质/前提 |
|---|---|---|
| accept_stage1_start_covers | stage1→stage2 | 第一步授权，实际规划结构验证+planning深度审阅；内部放行，user_confirmed=false |
| stage2_cover_options_ready_for_user_review | stage2→stage2 | 四封面齐全，展示规划摘要和封面后等用户 |
| approve_stage2_cover_style_start_image_deck | stage2→stage2 | 用户认可规划、选封面并授权step2；user_confirmed=true，记录规划与封面确认 |
| stage2_trial_first5_ready_for_user_review | stage2→stage2 | 前5含封面、实际审阅；结束暂停 |
| approve_stage2_trial_first5_continue_remaining | stage2→stage2 | 用户确认试样并授权step3全套交付；user_confirmed=true |
| accept_full_deck_start_stage3 | stage2→stage3 | 实际PDF和图当前有效，deck内容审阅及全稿视觉QA通过；内部锁稿，user_confirmed=false |
| stage3_outputs_completed | stage3→stage4 | 逐字稿和教案/方案Word/PDF真实齐全且package审阅通过；user_confirmed=false |
| stage4_deliverables_organized | stage4→stage4 | 已存在文件整理及manifest真实对应；user_confirmed=false，基础完成 |

修订decision保留`request_stage1_revision`、`request_stage2_cover_style_revision`、`request_stage2_trial_first5_revision`、`request_stage2_revision`、`request_stage3_lesson_plan_revision`、`request_stage4_organize_revision`。内容修订撤销相关内部验收与用户确认，未改变事实不重做。不要伪写旧的独立规划/PDF用户确认decision。

`confirmed.stage2_image_deck`不设为true；`controller_acceptances.stage2_image_deck`表示主控验收。锁稿包含实际PDF SHA和acceptance_actor=main_controller。第三步授权、实际试样确认和未来全稿内部验收分别存在。阶段3/4历史命名的布尔位只表示内部输出收口，不是人类审阅凭证。

## 内容审阅格式

使用`assets/templates/主题内容审阅模板.json`，scope planning/deck/package，controller_reviewed=true，reviewed_pages覆盖全部实际页，checks逐项写pass/fail及具体evidence，blocking_issues列事实/适龄/可实施硬问题。全部检查通过且无阻断项才能pass。脚本检查记录完整和指纹，不判断文本深度，不自动填证据。

主控需真实读取内容、案例和推理链，真实看图/看PDF，核对配套，不能只列页码或复制模板评价。审阅后的变更使basis失效，复审受影响内容。`quality`仅描述阶段质量状态，不能代替审阅证据。

## 恢复与动画

授权保存在workflow，正文保存在content，目标与来源保存在thematic_brief；不要另造正文。恢复见[恢复协议](恢复与防漂移协议.md)。动画通过独立inspection、plan、file_verification、background_manifest、background_review及stage5_animation状态记录，不用基础decision冒充动画完成；stage4完成字段不能因动画失败而撤销。全流程遵守[后台执行与验收规范](后台执行与验收规范.md)。
