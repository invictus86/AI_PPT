# 质量审查标准

> 当前1.2.0：三步基础流程见《阶段流程.md》。第一步规划经主控深度审阅可生成四封面，用户选封面并授权试做时才确认规划；第三步实际全稿由主控验收锁定，不新增PDF用户审批。主题活动内容与配套优先遵循《主题班会与家长会深度二创规范.md》《主题活动教案与会议实施方案规范.md》。

本文件保留详细质量检查项；QA、doctor、质量画像、主控判断和用户确认的职责分层以 `QA与doctor规范.md` 为准。

## 原则

质量审查分两层：

- 硬失败：真实性、确认点、目录边界、交付物存在、OCR覆盖权威正文或自动判通过等红线问题。
- 主控判断：审美、信息密度、页面是否太花或太空、内页复杂度是否合适。

Runtime 只适合检查硬失败。主控大模型负责判断审美和返工路由。

阶段3逐字稿与教案检查属于主控判断辅助：它可以提示内容一致性、口播自然度、DOCX/PDF 可读性、K12 教案硬问题和 manifest 覆盖缺口，但不能单独把项目判为通过或失败。

## 硬失败

以下情况不能交付或进入下一确认点：

- 缺少真实整步授权、规定节点的规划/封面或试样确认，或缺少全稿/配套实际主控验收。
- 正式图片不是来自中转精确 `gpt-image-2.5` 或符合《生图证据链》的GPT原生备用，缺少对应真实证据，或将原生结果冒记为中转结果。
- 未经合法batch manifest提交，或同组多张图片未按原要求并发调用；单个batch/run最多6并发，多个独立批次不共享额度，不增加全局生图互斥。中转服务限流单独记为技术问题，不能计作视觉返工或以此降低画质、任意切换中转模型/分组；明确故障的原生备用例外按《生图证据链》执行。
- fixture、本地渲染、source replay、HTML/canvas/SVG 冒充正式图片。
- 阶段3逐字稿或教案缺失，或 DOCX/PDF 不可打开。
- 阶段3逐字稿或教案引入与 PPT 冲突的新事实，且没有主控记录返工或风险说明。
- 阶段2或阶段3正式图的实际尺寸、目标尺寸或 `size_warnings` 缺失，导致清晰度风险不可追溯。
- 用户可见阶段目录混入 JSON、packet、日志、prompt 原稿等过程文件。
- 阶段1同时存在两个风格入口，或阶段2用户提示词文档存在坏链接、直接依赖未交付的 `_state` 附件、缺少当前正式图对应关系。
- 页数明显不一致或关键交付文件缺失。
- 阶段2B跳过试样直接生成全套正式图片，除非用户明确要求跳过。
- 试样未经用户确认就 promotion 到正式 `full_slide` results。
- 阶段2图片版 PDF 的 manifest 引用未确认试样、过期图片或缺少当前正式结果记录的 `img/` 文件。
- 阶段4整理生成占位文件、伪造缺失交付物，或把渲染失败的 PDF 图片当作成功。

## 主控判断

主控大模型判断：

- 风格是否合适。
- 四张封面是否有四种实质不同的媒介、质感或视觉表达，并符合相同主题、批准文字和适龄要求。
- 用户选中的封面风格是否被扩展到内页。
- logo、标题、页码、文字布局是否项目内统一；章节标签只有项目明确启用时才检查统一性，未启用时普通页没有章节标签不算缺失。
- 用户未明确要求时是否没有可见页码；用户要求时页码是否统一。
- 普通内页顶部小标题是否使用同一具体位置、字体、颜色和装饰，组件是否在计划中解析一次；未显式 opt-in 时是否没有额外章节标签。
- 多个模块介绍页是否使用同一具体结构，编号、标题和短说明是否只引用批准文字，没有后置重复追加。
- 专业型内页是否讲清楚。
- 演讲型内页是否足够简洁。
- 页面是否太花、太空或太满。
- 试样是否已经暴露整体视觉系统、版式语法或提示词问题。

## 阶段1

检查：

- 页数是否明确。
- 每页是否有清楚的信息目的。
- 每页是否有核心内容和辅助内容。
- 页面顺序是否有叙事逻辑。
- `PPT一致性.md` 是否存在，是否写清标题、模块页、页码、logo、公共元素、例外和禁用项。
- `图片风格.md` 是否存在，是否同时覆盖风格方向和图片提示词概要。
- `图片风格.md` 是否足够指导阶段2封面候选和后续图片生成。
- 是否没有把阶段1风格和图片提示词概要拆成两个正式用户可见文件。
- 是否符合用户目标和受众。
- 是否说明后续会先生成四张封面风格候选。
- `页面规划.md` 是否逐页写清最终可见中文文字、资料依据和内容保留边界。
- `每页干净逐字稿.md` 是否存在，是否逐页排版清楚，是否方便连续审阅每页内容。
- `每页干净逐字稿.md` 是否与 `页面规划.md`、`content.json`、`slide_prompt_briefs.json` 的每页最终可见文字一致。
- `design_contract.json` 是否写清路线、受众、资料边界、内容改写边界和封面候选策略。

主题活动的主控内容审阅还要给出以下实际证据，沿用现有内容审阅模板，不新增自动评分、检查键或审批节点：

- **具体性：** 指出关键任务页的对象、动作、产出及必要支架在哪里；只有“讨论/反思/制定计划”但无法开始时返工。不能仅凭篇幅变长或案例出现姓名认定增强。
- **真实材料与案例过程：** 按深度二创规范核对正式案例均为真人真事、主题契合、关键事实可追溯，两类常用课时的2—4例默认配置及偏离理由有据，核心/辅助用途明确且同一主线未重复计数。知名/有影响力人物优先须以贴题和事实可靠为前提，普通人的真实经历亦可；不能以名气替代经过。指出正文哪些页展开处境、困难、选择与后果，来源支持哪些细节；作品、知识示范、假设练习与视频引用另明性质，不混计真实案例。只挂来源、放照片、列履历或姓名加结论不足以通过；未证实的对话、心理与结果不能补成事实，缺口回材料与正文修订。核对PPT材料通俗易懂，现有备课依据和配套有可直接使用的讲述、问题、解释依据、可能回应、追问、过渡及时间，不将关键经过或必要材料留给教师另找。
- **推理与示范：** 指出案例要解决的信息缺口或选择、方法的中间过程与判断依据；人的感受/动机不由插图或单次表现直接推断。检查新任务是否需要理解，而非照抄即完成。
- **表达与主题：** 指出能让参与者理解人物或事情的具体细节，以及值得改变判断的新信息。人物说法须符合身份与处境，真实原话与转述分清；不以概念套话、煽情或插画替代感受。检查模块是否真正服务本主题，不能将不同主题一律收束为自律、错题、计划或打卡；方法练习只复述正确故事而未接触实际对象时返工。
- **页组连续性：** 用具体页码说明问题怎样推进，必要产物怎样检查、修订或迁移；只有目录顺序合理、每页各有活动而互不接续，不足以证明整套组织良好。也不为统一形式强迫所有任务共用一份卡片。
- **关系与版式：** 说明比较维度、流程节点、功能分区或读序如何准确承载内容；人物/背景漂亮不能抵消关系错误或挤掉示范。已生成页面还须查看正文、图片内小字和风险局部，编辑后整页重查。

证据分别进入既有`substantial_enhancement`、`freshness_and_sources`、`practical_activities`、`transfer_and_reflection`、`expression_and_visual_intent`等适用项；不新增检查键。主控需指出实际细节与不足，不能以“有案例、有活动、有计划”统一填pass。上述内容在deck审阅核对实际页面是否保留，package审阅核对口播是否忠于来源且未补造事实。示例和经验机制用于设计与主控判断，不能用关键词命中、卡片数量或结构校验冒充内容质量。试样只支持已看页面的判断；完整规划不冒充完整成品或真实授课效果。

整课取舍、关键难点页组、教师操作准备和时间安排在阶段1已有审阅中判断；实际成图在原有视觉QA中判断信息关系、读序和完成度。不得另加A/B对照、专项难页试做、教师试用、试用反馈收集或新的用户批准条件。课堂中的练习与反馈属于教学内容，不因此删除；原有内容、文字、排版及全页审阅保持。

## 阶段2A

检查：

- 图片来自真实正式生图路线：中转精确 `gpt-image-2.5`，或符合《生图证据链》的GPT原生备用；提示词、参考图与high/PNG、尺寸验收要求不变，工具未开放参数须如实标记。
- 图片默认目标尺寸为 `1672x941`，实际尺寸、目标尺寸、目标容差、偏好底线和 `meets_target_size`、`meets_preferred_size` 已入账；低于 `1600x900` 的结果作为清晰度风险由主控判断。
- 比例按实际宽高单独核算：目标16:9，默认相对误差容差2%且包含边界；超出时保留原图和warning，由主控核对，不用最低宽高代替比例通过。字段与算法见 [生图证据链.md](生图证据链.md#尺寸和清晰度策略)。
- 四张封面各自的媒介、质感或视觉表达有实质差异；共同批准文字、适龄、安全与真实性限制一致。
- 四张封面是否基于 style card，有清晰差异、内页延展和风险说明。
- 用户可见目录提供封面图和同一份成功提示词文档；用户选择记录放在 `_state/阶段2/cover_options/selection/selection.json`，内部候选卡和请求记录不混入。
- 用户选择后已写入 `deck_style.json` 和 `layout_intent.json`。

## 阶段2B

检查：

- 图片来自真实正式生图路线：中转精确 `gpt-image-2.5`，或符合《生图证据链》的GPT原生备用；提示词、参考图与high/PNG、尺寸验收要求不变，工具未开放参数须如实标记。
- 正式页面图和试样都按 `1672x941` 默认目标生成并保留尺寸记录；如低于 `1600x900` 优先底线或发生降采样，已作为清晰度风险记录。
- 试样和全量图执行与封面相同的独立比例检查；比例偏差、分辨率不足和文字不清分别报告。旧图缺比例字段时只读核算，不补造历史或自动撤销确认。
- 是否先展示总共5页试样并让用户确认，含已选封面，通常新生成4张内页；默认严格前5页；只有用户明确要求才在名额内替换复杂页或调整数量。
- 试样通过后是否保留证据并 promotion 到正式结果。
- 试样失败时是否默认返工阶段2设计规划和提示词，而不是修改阶段1内容资产。
- 全套图片使用用户选中的视觉系统。
- 用户未明确要求时没有可见页码。
- 普通内页顶部小标题没有漂移。
- 模块介绍页像同一母版重复使用，没有随机换结构。
- 中文文字可读。
- 不出现英文占位、乱码、假字。
- 主视觉和页面主题一致。
- 每页之间风格统一。
- 新prompt是否只含横版画面要求、批准正文和必要限制；尺寸由参数设置，来源说明在代码块外；旧成功快照保持当时原文。
- 信息层级清楚。
- 图片不是纯装饰图。
- 如已记录 `_state/阶段2/visual_qa/stage2_aesthetic_review.json`，其中返工建议应指向正确范围。
- 图片版 PDF 可以打开。

阶段2审美保留合理容差，但文字完整性、内容真实性、教学关系/比例/方向、安全示范、可读性及人物/物体结构为阻断项。实际全页、原尺寸文字与风险局部分别检查；每张编辑图重查整页，不因局部修复忽略新错误。主要检查：

- 视觉系统一致性。
- 文字可读性。
- 内容文字准确性。
- 页面角色匹配。
- 图片相关性。
- 无伪文字和占位符。
- 密度和层级。
- 页码默认关闭或按用户要求统一。
- 顶部小标题一致性。
- 模块介绍页一致性。

阶段2审美 QA 是主控展示封面/试样或内部锁定实际全稿前的视觉复核，不是自动视觉评分系统，不替代用户确认，也不让 runtime 自动判断审美。它的记录文件为：

```text
_state/阶段2/visual_qa/stage2_aesthetic_review.json
```

`review_scope` 只使用三个范围：`cover_options` 表示四张封面候选，`trial_first5` 表示阶段2B试样，`full_image_deck` 表示完整阶段2图片版。建议记录 `overall_status`、`review_scope`、关键检查项、逐页 findings 和 `rework_recommendation`；如果整体通过但仍有单页 finding 要求返工，必须把整体状态改成 `needs_rework`，不能写出自相矛盾的 QA。

三个范围都必须有逐张`text_reviews`及`text_review_basis`，对照阶段1每页干净逐字稿和同源content，实际查看最终保存全图，逐段分别记录完整性与字形检查；疑字查看原图局部并记录处理，不能靠语境、段落完整或OCR一致放行。四封面按A/B/C/D分别覆盖，试样含复用封面，全稿覆盖全部实际页；缺图、漏区、重复、未看全图、任一检查未通过、未解决疑字及指纹过期均不能展示或锁稿。返工后核对修改处及整页副作用；三个范围记录分别保留，最小字段和命令见《首轮生图与返工规范》的“逐张文字检查与记录”。

返工路由按问题来源决定：封面候选整体不合适回 `stage2_cover`；已选封面可用但画面本身不可交付，回对应封面或 prompt；试样暴露视觉系统抽象错误，回 `stage2_design_plan`；普通页文字不清、构图跑偏或图片无关，回 `stage2_prompt` 或 `selected_slides`；未请求却出现页码、页码不统一、顶部标题漂移、模块页骨架漂移，先回阶段2设计来源，更新 `图片风格.md`、deck/layout 组件和受影响页 `image_prompt_plan`，再重新派发完整 prompt。

试样确认和全稿内部验收分别记录。图片生成成功不等于内容或视觉通过；第三步授权不等于用户看过未来全稿。实际全稿经主控深度和视觉审阅锁定，质量判断说明具体依据与返工范围，不新增PDF用户确认。

阶段2审美 QA 禁止事项：

- 不做像素级自动评分。
- 不要求每页完美。
- 不因轻微对齐差异阻断用户确认。
- 不让 runtime 自动判断审美。
- 不把试样确认或第三步授权当成实际全稿内部验收。
- 不为省 token 强行复用有明显文字、构图或证据问题的已选封面。
- 不在既有 prompt 末尾反复追加“其余不变”，应回到来源计划修正后重新派发。

## 阶段3

检查：

- 阶段3母版为实际全稿PDF，已由主控内容/视觉验收并锁定SHA；用户授权第三步，不虚构全稿用户确认。
- `speaker_script.json`按现行schema组织全局信息及逐页内容；每页`script`只放口播，`teacher_notes`、`response_branches`、`grade_adaptations`按需使用现有字段承接操作提示、可能回应与替代用法，和口播分栏/分段呈现，不因旧“每页只保留三项”口径删除教师支持。
- 逐字稿不是页面文字照读版；每页内容自然、通顺、足够展开，且没有引入与 PPT 冲突的新事实。
- 如用户要求调研补充、页面内容明显偏薄，或主题属于高准确性场景，已按内容需要使用权威来源校准口径，并在 `_state/阶段3/`、manifest 或阶段决策中记录来源用途；不要为了完成流程堆来源。
- Word 版存在、可打开、使用结构化样式、第一页顶部题头、页眉页脚、中文字体与语言属性，以及每页讲稿区块；没有单独封面页。
- PDF 版存在、可打开、文字可选择，不是整页图片拼接，内容与 Word 来自同一份讲稿数据，并优先嵌入中文字体。
- Word/PDF/Markdown 逐字稿文件名使用 `<封面第一页主题>｜逐字稿`，没有退回 `演讲逐字稿.*` 这类固定旧名。
- Word/PDF 无明显截断、重叠、乱码、孤立标题或表格溢出。
- 验证环境具备时，PDF全部页面与DOCX实际后台排版页均有主控文字、字体、表格、分页和布局观察；确认第一页题头后直接进入第01页内容。使用render-document-background和record-document-layout-review绑定来源与全页图片指纹；ZIP/XML仅辅助检查内容，独立生成PDF不能冒充DOCX排版证据。缺环境时按文档后台规范记录verification_skipped及未视觉验收状态，继续其他制作交付但不冒称已验证；已有环境的执行失败或已发现问题仍须处理，不能用缺环境例外跳过，也不能前台打开Word/WPS。配套内容仍需主控审阅，脚本按真实环境能力核对相应文档审阅或缺项记录。
- `_state/阶段3/speaker_script_manifest.json` 记录 DOCX/PDF 路径、sha、PDF 生成工具和检查状态。
- 如有返工，返工阶段和原因明确。

K12 教案设计额外检查：

- K12 触发条件明确；只说“课件”但缺学段、年级、教材、学科等信号时，不能直接标记 `education_context.is_k12=true`。

- `_state/阶段3/lesson_plan_context.json` 只在材料较多、来源冲突或旧项目缺少教育上下文时按需生成，不作为阶段3必经大文件。
- `lesson_plan.json` 或等价薄输入由主控撰写，不能把教案结构塞进 `speaker_script.json`。
- 教案活动不能修改 PPT 页面、页数或阶段1已确认内容；发现阶段1与教材冲突时，必须写入 `source_conflicts` 和教师确认项。
- 每个核心教学环节在内部能追溯到 PPT 页码或教材材料；教师可见过程表不把“时间”“PPT/材料”做成机械固定列。
- 教学目标、课堂活动和评价证据有对应关系。
- 教学方案应呈现课堂任务链，核心环节有关键提问、追问纠偏、学生产出和评价证据；如果只是“教师讲解、学生回答”的短提纲，由主控扩写修订，不交给 runtime 硬判。

- K12 教案不以页数定质量；PDF 页数只记录排版结果，不因低页数或高页数自动 warning、失败或补写。
- 教案 Word/PDF 可打开、文字可选择、中文不乱码，不是整页图片拼接；不得因强制分页导致标题或短块内容单独占页形成大面积空白。
- `lesson_plan_manifest.json` 记录 Markdown/DOCX/PDF 路径、sha、页数、渲染模式、学科组、PDF 文本探测和 Word 表格模式；完成前 manifest 状态应为 `generated`。
