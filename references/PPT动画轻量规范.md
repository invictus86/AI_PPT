# PPT 动画轻量规范

规则修订：2026-10-31。本规范及题答专项是当前动画运行依据，历史调研/规划不覆盖这里的规则。

适用于 `/动画`、`/加动画`，两入口等价。默认读本规范；遇提问、练习、病例讨论再读[题答动画处理规范](题答动画处理规范.md)。首次写计划或归组不确定时，按需读[动画编排与执行示例](动画编排与执行示例.md)相应部分，不加载研发报告。

## 1. 目标、红线与当前能力

默认尽量覆盖全部可处理页面：能加动画的页都加，包括封面、目录、章节页、结束页及完整页面。根据内容选择整块入场或分步揭示；无需分步时用一次轻量淡入，不因此整页静态。普通执行不新增确认轮次，用户只要求分析时不写PPT。

只用当前宿主（Codex 或 WorkBuddy）自带的 Bash + Python 标准库，不依赖宿主专属插件或 MCP。

默认直接更新选定PPTX，保留本地目录与唯一当前稿规则，并在同目录规范为`<主题>_可编辑动画版.pptx`；已是规范名则原位更新，不另存或递增版本，不覆盖归属不明的重名。原稿快照继续放内部_state/阶段5/originals，动画记录在_state/工具任务/animation。仅改动画时间树；任何文字、元素、背景、图片、字体、样式、坐标、尺寸、分组、图层顺序均不增删改。不拆框、解组、重绘，不新增遮罩、聚焦框或辅助图形。

当前 `linear_fade_b_v1` 支持顶层独立对象或整个组的350ms点击淡入，同一步全部成员同步；显示后保留，后续步骤累计出现。执行器保留静态页面能力，仅用于用户明确指定或当前无法安全加动画的例外，不作为默认编排。不支持退出、逐字、路径、循环、自动延迟答案、点击指定物体触发、退页自动重置或仅控制组内子对象。不能把“聚焦”写成当前已有的高亮/变暗效果；可揭示现成注释和引线来引导注意。

## 2. 先判断页面任务，再选初始状态

每页只判断：观众要阅读、比较、观察、理解顺序，还是先思考再回答？初始画面提供完成这项任务所需的上下文。场景只调整侧重点，不代替页面判断。

**切页首屏不得空白。** 进入页面、首次点击之前须有可辨识的原有背景、主图、标题或必要上下文；禁止停在全白、全黑或空底色上，等待额外点击才显示整页。页码、页脚、微小装饰不作为有效上下文，纯色底也不等于已有可辨识背景。普通页默认主标题初始可见、正文按完整块点击展开。主标题需要动画时可先点击出标题、再点击出正文，但首屏已有可辨识背景/主图；不强制每页多一次仅出标题的点击。题干、条件、普通选项、作答要求及必要提醒可与标题同首屏，不为标题顺序隐藏必要信息。母版/版式中真正显示的内容可以承接首屏，但不能仅因文件里存在母版就认定有背景。

发现空白开场时，重新划分初始可见与后续完整块，保留安全可用的主体动画，不能把受影响页批量改成全静态来代替重编排。旧计划可作参考，仍按当前页面内容与对象核对。静态例外须有当前页具体依据；“完整阅读、方便书写、无需分步”不能单独证明该页无法安全加动画。仅一张整页图/不可拆整组、又没有其他可辨识首屏内容时，不隐藏整个对象等待点击；保留初始可见并说明受限。题答同图仍按题答专项列为需分层，不能以静态全显答案声称处理成功。

下表按页面任务取舍。主标题默认先于对应正文，必要材料可同首屏；正文已显示后才补普通标题属于默认复核项，优先调整标题先见。先观察材料后揭主题、讨论后归纳或标题本身透露答案时，可有依据地后出，记录当前页具体教学理由。不要按字号、坐标或问号猜角色。卡片内部小标题不是页面主标题，仍与本块正文、编号、图标、专属底板和引线同步。无需分步时主体一次淡入；不能用批量静态、页脚或装饰凑覆盖。题答按整组页面核对，不因答案页缺少重复题干就判错。

| 页面任务 | 初始可见（S0）的可选安排 | 后续编排建议（可调整） |
|---|---|---|
| 封面 | 可辨识背景或主图；主标题可先见 | 默认主标题先于副标题/说明；一体化标题块可同步 |
| 目录 | 标题与必要背景 | 条目可全部同步、分组或逐项出现，标题不晚于对应条目 |
| 章节、结束 | 可辨识背景/主图或主标题 | 默认主标题先于引导语/结束说明；同一完整块可同步 |
| 多个独立对象组成的完整页面 | 必要背景或上下文 | 可整页主体一次淡入，也可按语义块先后出现，完整页面不等于必须同步 |
| 单张整页图或不可拆原有组 | 可辨识的独立背景或其他必要上下文 | 只有首屏仍有效时才可整图/整组入场；否则原对象初始显示，作为有依据的静态例外；不拆图、解组或假称支持内部先后出现 |
| 并列观点、方法清单 | 必要上下文；标题可先见或先入场 | 可一起出现，也可按观点/方法分块先后；一起比较时宜同步，逐项介绍时宜分步 |
| 流程、故事、因果链 | 标题、起点、必要条件 | 按真实顺序推进，相关箭头随对应步骤出现，已出内容保留 |
| 图像、作品、证据细读 | 主图、必要标签/图例/出处 | 按观察节点同步出说明、局部图、圈注和引线，主图保持完整 |
| 对比、方案选择 | 可供理解比较的材料和指标 | 解释可同期对照或先后介绍；需要先比较再判断时结论后出 |
| 提问、练习、病例讨论 | 主标题与真实题干、条件、普通选项、必要材料 | 答案/提示点击出现，独立解析随后；跨页已有题目不复制 |
| 总结、行动建议 | 已知上下文 | 结论与行动建议可整体出现，也可先结论再建议，按讲述层次安排 |

问号只是线索。引导性标题不自动认作考题；没有答案的开放问题不编造答案。图表或作品中的信息本身通常是观察材料；含直接写出的答案、正确标记则按题答专项处理。

## 3. 完整块怎样归组

先按意思确定块，再用位置、大小、共同容器、样式辅助匹配对象。XML顺序、对象同名、距离近都不能单独决定归组。

| 对象关系 | 默认归属 |
|---|---|
| 同一卡片或语义块的标题、正文、编号、图标、专属底板和局部装饰 | 已确定为同一完整块时全成员同次出现；可独立讲述的标题/说明可另成块，不把整页强并为一块 |
| 主图与某处细读的局部放大图、引线、说明 | 需要先观察时主图先见，其余归入细读步骤；无后续说明的独立主图，仅在另有可辨识首屏上下文时整图一次淡入 |
| 指向某个步骤的箭头 | 随该步骤出现，连接关系两端应已可理解，不先出指向空处的箭头 |
| 全页背景、共用容器、页码、定位用公共标题 | 可静态，不因覆盖多块而重复分配；封面/章节/结束页的主体标题在首屏已有其他有效上下文时可归入入场块 |
| 题干与答案共用一个不可独立控制对象 | 不把整个对象当答案隐藏，报告该页需要分层 |

一个对象只归属一个单元。先定共享对象，再处理各块专属成员；确属共享的对象保持静态。重复卡片用同样的成员规则，不能首张只动文字、后面动整卡。完整块的成员同步要求不等于整页同步；封面主标题、副标题、署名或不同目录条目可作为独立单元先后出现。

剩余对象归入静态前，核对其中是否有答案、正确标记、结论、提示，或应随块出现的底板/引线。不能用“其余全部静态”替代判断。无需给每个装饰写解释，只记录难归组或有歧义的情况。

## 4. 点击节奏：每次点击对应一个值得停顿的节点

- 默认每个可处理页面安排至少一次主体入场；没有顺序、观察或互动分步需求时，整块一次淡入。仅用户指定静态、没有可动画对象或当前能力无法安全处理时保留静态/跳过，并简短说明原因。
- 同步或先后由阅读与讲述需要决定，不按页型预设统一答案；短小并列内容可同步，也可分块先后，不按段落数、对象数机械分步。
- 流程、因果、故事按理解顺序；题答按人工思考关口。标题、正文、图标组成同一完整块时同步；能独立承接讲述的主标题与说明可分步，默认标题先于说明。
- 结论可整块出现或按层次揭示。不要把每页末句机械地再安排一次点击，按观察、讨论和总结关系选择先后。
- 普通页面通常1–3次；超过3次时核对每步是否有独立讲述目的。这是节奏提示，不是硬上限、配额或新增审批；完整流程和互动优先。
- 同类页保持可理解的节奏，内容关系不同可换方案；主标题默认先见或先入场，必要材料及一体化块可同步；有教学依据的后出标题记录具体例外，不设固定点击次数。当前先后通过分次人工点击实现，不新增自动延迟或同次点击后自动错峰能力。

## 5. 场景只调整默认侧重点

| 场景 / scene | 调整规则 |
|---|---|
| K12 / `k12` | 保护思考时间；题干、条件、普通选项可读；正确标记与答案不提前出现 |
| 商业路演 / `pitch` | 观点与证据对应成块、图表完整；结论是否后出取决于讲述关系，不套课堂提问模式 |
| 医护 / `healthcare` | 必要提醒和关键上下文先见；流程有序；病例判断与依据按题答关系揭示，不隐藏必要提醒来制造悬念 |
| 大学生比赛 / `competition` | 创新点与证据成块、实施步骤有序；一个创新点不拆多个碎片点击 |
| 答辩 / `defense` | 研究问题、图表标签和证据上下文完整；解释按需揭示，密集表格保持完整，可整表一次淡入；需要初始作为证据时先见，配套解释点击出现 |
| 未指定、混合或其他 / `general` | 按页面任务处理；艺术鉴赏有细读时原作先见、注释点击出现；只有原作展示且另有可辨识首屏上下文时整图一次淡入，否则按单图静态例外处理，不新增scene枚举 |

无场景要求就从内容推断或用general，不追问用户选择风格。scene是上下文标签，不会让执行器自动推断不同动画；页面编排由主控落实。

## 6. 最短执行路径

1. **定位文件及关联项目。** 显式附件/路径→会话确认主PPT→项目明确主PPT→相关目录唯一PPTX。用户指定的候选稿可用；排除锁定、临时、测试文件，不按mtime猜版本、不全盘扫描。无候选/同级多候选才问一次。先找已有同名或已绑定项目及动画任务，找不到才在 `PPT输出/<中文项目名>/` 建动画附属任务，不补造阶段文件。
2. **读取一次，按需细看。** inspect返回摘要和完整inventory路径。所有将处理页面的文字与对象清单必须纳入判断；图片/组内容不清、引线归属不清、疑似题答时才看相关源图或可信预览。预览来自当前源或可核对其对应关系，其他版本缩略图只能参考。不能只看标题和计数就全稿套模板。
3. **内部写短计划并绑定对象。** 用“页号｜任务｜S0｜点击1…｜特殊限制”即可；相似页沿用模式，只核对成员差异。完整归属静态/动态单元，同时核对首屏非空白及动画覆盖：逐页对照用户授权范围与完整inventory，每个可处理页已有主体入场或具体静态例外，未选页须列明当前页排除依据，不能把未选页当成已处理或只查没有白屏而漏掉动画被批量撤除。题目与必要材料先见、防露答优先，不为凑动画隐藏必要提醒。不能给所有对象强加独立点击。不向用户逐页输出长分析，也不要求确认短计划。调用格式按需读示例，不每次研究XML写法。
4. **只执行支持范围。** apply验证后更新当前PPT并按本地命名规范更名。已有时间树默认reject；本工具既有任务、当前文件匹配after哈希且原计划仍适用时，复用task验证/返回已应用。用户明确要求重做已知选页时，用新task、最新源绑定及replace_selected限定替换；未知既有交互不盲合并或覆盖。源变更重新inspect，不强改旧hash。自动翻页与人工揭示冲突时列为限制，不顺手改播放控制；锁定来源冲突报告具体引用，不改主阶段确认。
5. **简短回报。** 原文件路径、处理页/主要方式、具体跳过页、验证状态即可。apply已含文件验证；verify用于恢复/复查，普通成功不重复整套实验或测试。

```bash
python3 .skill/scripts/pptctl.py animation inspect --run-dir "<项目>" --task-id anim_001 --source "<PPTX绝对路径>"
python3 .skill/scripts/pptctl.py animation apply --run-dir "<项目>" --task-id anim_001 --plan-file "<计划JSON>"
python3 .skill/scripts/pptctl.py animation verify --run-dir "<项目>" --task-id anim_001
```

python3使用当前宿主可用解释器，不安装额外动画依赖。inspect可接 `--active-ppt`、`--project-ppt`；省略时仅查项目根及直接阶段目录，不能假定CLI能读取会话或自动搜索项目库。`--page N`查看单页详情。内部资料落 `_state/工具任务/animation/<task-id>/`，task-id用字母/数字/下划线/连字符；工作区/Skill根不能作为项目。

短计划中的任务类型和普通编排理由放任务备注，静态例外使用下述`static_reason`。JSON只用当前[schema](../scripts/schemas/animation_plan.schema.json)支持字段，ID/part从inventory取，source路径与hash原样继承。`click:0`是初始可见，1、2…是连续人工点击序号；不同unit同序号同步，数值不是延迟毫秒。

全静态的执行页另填页级`static_reason`，写明本页对象限制、必要信息或用户明确要求的具体依据，不用泛泛的阅读/书写理由。它是现有计划里的短说明，不新增用户确认或独立表单；不要给动态页保留过期静态理由。仅图片或继承内容承接首屏时，查看当前来源的相关源图/可信预览后填`visual_checked:true`，确认并非空图、空底色、微小装饰或被遮盖的背景。可复用仍有效的已有证据，不要求额外全稿渲染。旧inventory缺少首屏来源信息时，按最新源用新task-id重新inspect；不通过改写旧指纹或伪填看图记录放行。

## 7. 三种检查各自证明什么

- **主控内容检查：** 对照原文和必要图像，确认角色、归组、S0可理解、点击有目的，尤其查静态组是否泄答。程序不能替主控看懂内容。
- **程序文件检查：** 对象归属/时间树合法、执行与计划一致、非动画内容和资源未变、并发/重复保护；写入前和结果文件复核初始可见来源，拦截明显空首屏，报告源文件总页数、选页/动画页、未选页清单及逐页静态理由；主控对照授权范围复核未选页与例外，不凭选页通过率宣称全稿完成。纯色背景、母版占位提示、隐藏的母版图形不能充数；图像/继承首屏的有效性和静态理由是否成立仍由主控实际审阅。全ID覆盖不代表角色正确；不能靠改成content或静态来绕过真正的题答/归组问题。结果的teaching_relationships列声明的标题顺序、跨页题答锚点及仍须主控复核的范围；未声明的标题不冒称已被程序识别。
- **原生放映检查：** 首屏、停留、逐点击、退页与重放是否符合预期，按软件和文件记录实际观察。历史B结构五页用户确认可用，不代表当前文件或所有题型已实播；无观察就标待验，不反复请求操作许可。

无法可靠处理的页列出页码与原因，从本次apply选页中排除，其他支持页可继续。`needs_layering:true`表示该页不能apply，不能以静态全显答案宣称成功；若全部页均不支持，不写PPT。任何内容保护失败都不保存。

## 8. 主标题与跨页关系的紧凑声明

新计划中，确认为独立页面主标题的unit标`is_title:true`，对应正文/任务unit用`title_id`指向该unit.id；程序只核对显式声明，不从文字、字号或位置猜主标题。正文click不得早于标题；同首屏/同一步完整块可同步。确有观察后揭题、标题直接给答案等情况，在主标题unit写非空`title_exception_reason`，主控审阅理由。含答案的标题仍用answer角色并与同题答案同步，不能为标题先见泄答。内容块内部小标题与整块共用一个unit，不套主标题关系。

字段为schema 1.0的加法扩展；旧任务文件可以读取，但其未声明标题页列`undeclared_title_pages`，文件通过不等于已满足新语义规则。新编排须按真实页面声明关系；无独立主标题不凭空新增对象，保留主控判断记录。旧计划重新使用前复核角色和顺序，不重写历史指纹。跨页关联使用顶层`question_refs`，具体合同及例子见[题答专项](题答动画处理规范.md)和[执行示例](动画编排与执行示例.md#e1-主标题先见与跨页题答)。
