# 阶段流程 · 推荐二合一与可选分步

内部阶段目录0—4保留，用于定位证据；对外优先展示“第一步＋第二步第三步二合一”主流程，原第二步、第三步作为可选分步。默认不支持旧项目状态，不自动迁移。每次恢复先读state、decision、events、resume-brief及实际输入/产物，执行前drift-check。

内容、编排、教师使用和视觉质量优化融入下列原有步骤，不新增对照验证、专项样张、教师试用、试用反馈收集或额外审批。原有选封面、分步方式的前5页确认和主控内容/成图/配套审阅不变；明确选择二合一时按下文快捷入口处理；教学设计中的学生练习、课堂反馈和产物修改照常保留。

## 第一步：资料整理、深度规划与封面

1. 按[项目目录规范](项目目录规范.md)先从原始主题文件夹继承明确编号及前导零，再新建`PPT输出/<中文项目名>/`；编号仅用于项目目录，不自动进入交付文件名或封面。注册资料，提取PPT可见文字、图片文字、备注、页序和原主题框架。单纯XML取文本不覆盖图片内字，环境具备时必须通过后台渲染页面及媒体图审阅/OCR；缺环境不执行对应验证，继续可读取资料并明确列出未验证图文，不冒称完整审阅；使用extract-ppt-background或render-ppt-background，不打开前台Office/WPS。整理有效框架、陈旧/不适用内容、保留事实和可增强空间。原稿及配套为参考；视频等不同形式按新课实际需要读取和判断去向，提取成功不等于内容已理解，不要求逐项保全原稿。
2. 主控从真实用户要求记录`authorize-step --step 1 --evidence <原话>`。若明确仅阶段0，只整理并停止，不记录覆盖规划封面的授权。
3. 将四项可改值和自动判断写成settings文件，再`configure-project --settings <文件>`。默认学段通用，不追问具体年级；来源不足时仅澄清影响目标的关键问题。value/source/evidence用于内部，不让用户填完整表格。
4. 主控先确定整课问题与取舍，写主题深化、目标/任务/时间、案例推理、关键难点页组、实践与行动后再规划页面；关键活动的材料、教师指令、不同可能回应、追问和备用处理在规划时形成。按深度二创规范检查单页必要信息与跨页理解连续性；重要素材转化、替换或省略后，确保问题依据、任务材料、解释、过渡及时间完整，关键取舍写入现有规划，不新增流程或确认节点。`create-stage1-draft`提供壳，不自动生成内容。维护content.json、design_contract.json、slides、briefs、版式安全；正文从content同步派生规划和阅读稿，执行`sync-stage1-derivatives`。
5. 四份规划实际完成并`validate-stage1`结构通过后，主控按深度规范逐页及联读关键页组自审：核对叙事与推理支点、问题回收、故事/讨论收束、页组承接和整课主题表达，以实际页码、关键文字及关系作证，不以页面目的或设计标签判优。`record-content-review --scope planning --review <文件>`保存既有检查项，结构通过不替代内容判断，不预填pass。
6. `make-decision --type accept_stage1_start_covers --notes <实际审阅结论>`，执行该decision；不使用`--user-confirmed`。按当前生图模式生成四个封面候选，默认派发省略`--route`读取本机/项目设置；内置模式直接调用当前聊天生图工具，不尝试中转，自动备用按《生图证据链》处理中转优先和故障交接。候选齐全后仍由主控逐张看图、对照阶段1每页干净逐字稿校对，按《首轮生图与返工规范》用`record-stage2-visual-qa`记录四张全部通过；才可`stage2_cover_options_ready_for_user_review`，展示规划摘要和4封面，暂停。

规划未由用户确认时可以在第一步内部生成候选；实际内页仍不可生成。

## 推荐主流程：第二步＋第三步二合一

选定封面并认可规划后，优先推荐使用二合一，明确授权先试样、后全稿和配套整理；原第二步、第三步保留为后面的可选分步。推荐不替代授权，也不改变已有项目的实际授权；使用[统一二合一提示词](../assets/templates/第二步与第三步二合一提示词.txt)，无需再发送第三步命令。

1. 在封面选择节点，先根据用户实际选择准备selection.json、deck_style和layout_intent，再执行`authorize-step --step 2-3 --run-dir <项目目录> --evidence <用户连续制作原话>`。它独立保存二合一授权，绑定当前正文、目标及已选封面，不预填未来试样确认，不生成虚假的step3授权。然后照常执行`approve_stage2_cover_style_start_image_deck --user-confirmed`，该确认只对应当前规划和封面。
2. 转正合格封面并完成前5页（含封面），保留原试样派发、逐张文字/字形/视觉/教学用法检查和返工。不得调用trial-skip冒充二合一。`record-stage2-visual-qa`记录通过后进入`stage2_trial_first5_pending_controller_acceptance`，责任方仍为main_controller。
3. 主控核对有效连续授权、五页当前图片与逐张QA，显式执行`accept_stage2_trial_first5_continue_remaining`，`user_confirmed=false`、`controller_reviewed=true`。仅设置内部`controller_acceptances.stage2_trial_first5=true`，用户试样确认保持false。复用有效试样，继续原第三步的剩余图、图片版PDF、全稿验收、锁稿、配套审阅与整理，不新增人工等待。
4. 可自行解决的文字、排版和视觉问题先返工复查；必须改变已确认方向、核心内容、受众、页数范围，或存在无法自行解决的关键阻断才暂停。正文、目标或所选封面变化使原授权失效，不能静默扩大范围；图片或试样集合变化使相关QA失效，重新审阅后放行。
5. 未使用二合一的项目仍完成试样后暂停，必须有真实用户确认及第三步授权。用户在封面节点改用普通第二步时，重新记录`--step 2`会撤销该节点的二合一授权；不凭历史偏好替项目切换路线。

## 可选分步：第二步·前5页试样

用户认可当前规划、选择封面并授权试做，记录step2授权，构建选择文件、deck_style和layout_intent，再`approve_stage2_cover_style_start_image_deck --user-confirmed`。该真实节点同步记录规划确认。

检查选定封面并转正，不重画无问题封面。默认前5页含封面，只派发缺失的4张内页；已有有效页可复用，指纹和内容仍需一致。复杂页替代或试样数量调整只有用户明确要求才能使用。实际审阅文字、视觉、内容与教法，包含复用封面在内逐张对照阶段1每页干净逐字稿校对并用`record-stage2-visual-qa`记录全部通过后，才进入`stage2_trial_first5_ready_for_user_review`，展示前5页，暂停。

## 可选分步：第三步·全稿、配套与整理

1. 用户确认试样并授权整套制作/配套/整理，记录step3授权，再`approve_stage2_trial_first5_continue_remaining --user-confirmed`。只说试样不错而未授权继续不能自动扩大范围。
2. 复用有效试样，生成剩余页，打包真实图片版PDF。此时`full_deck_pending_controller_qa`，主控继续，不等用户单独PDF确认。
3. 实际看完整PDF和每张页面，对照阶段1每页干净逐字稿逐张校对文字并记录全部通过；依据deep criteria联读实际页组和全稿，检查规划中的叙事、认识收束、内容关系和主题表达是否真正呈现，再写deck内容审阅，按视觉QA写`record-stage2-visual-qa`。文字与规划一致不等于内容质量通过；不以已通过的封面/试样范围记录替代完整范围记录。母版、图片或文字源变更使对应记录失效，失败修相应部分，不用未来授权代替验收。
4. `accept_full_deck_start_stage3`内部decision，无`--user-confirmed`。锁定真实PDF路径/sha与内部验收依据。主题班会与家长会都设置配套必交，无教材不阻断。
5. 按锁稿和规划时形成的操作依据，用场景模板整理一份班会教案/会议实施方案结构数据，`build-lesson-plan`；写逐页自然口播、操作提示、可能回应与少量年级替代用法，`build-speaker-script`。不能到配套阶段才补出PPT未支撑的核心任务。均输出Markdown、Word、PDF，后两者是正式交付。
6. 实际检查所有配套文字、版面、页码标题、时长与活动可执行性，再记录package审阅。`stage3_outputs_completed`内部decision进入stage4。
7. `organize-deliverables`仅复制现有图、图片版PDF、干净文字、逐字稿和教案/方案Word/PDF，可用pdftoppm派生配套PDF图片。真实manifest通过后`stage4_deliverables_organized`收口；不检查PPTX。

## 后续顺序

基础交付 → 用户手动PDF转可编辑PPTX → 可选Canva修订及自动导出下载 → 本地文字字体排版优化 → 外部轻量动画。跳过Canva可直接用转换后最终PPTX。用户同时授权字体兼容修复时，按清单将显示异常所在整句话或标题改为本机可用的常见相近非会员字体并判断加粗；用户已授权可编辑文字优化时按《可编辑文字优化规范》连续轻微修字体/格式/文本框并还原明确转换错误，同次授权包括原版相近匹配与Canva交接；旧窄范围任务仍按原授权，纯动画请求不改字体。修订保留文件差异、实际字体/排版预览与结果审阅；新动画按轻量规范按需看图及核验文件/时间树，不强制全部点击状态渲染，不打开前台Office/WPS。动画成品直接更新本次选定PPT并在输入同目录规范命名，不另存或递增版本，不创建用户可见阶段5文件夹；重名保护与旧稿收拢按[唯一当前稿规则](交付文件命名规范.md#可编辑ppt的唯一当前稿)，修订与原稿证据保存在项目内部`_state/阶段5/`，轻量动画任务保存在`_state/工具任务/animation/`。动画单独交付，不重新打包stage4。参考[可编辑后续一体化规范](可编辑后续一体化规范.md)。

## 失败与修订

从真正失败环节继续，保留无变化且核验有效的产物。内容/学段/场景改动回stage1，连带重新确认受影响封面或试样；视觉问题回stage2、口播/方案问题回stage3、动画问题只回stage5。用户只要资料整理仍硬停stage0。脚本和文件存在均不替代主控决策或真实用户授权。
