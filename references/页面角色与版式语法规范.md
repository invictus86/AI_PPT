# 页面角色与版式语法规范

## 目标

本规范为阶段1页面规划、阶段2 prompt 和阶段3逐字稿/教案输出中的锁定稿理解提供统一的页面角色语言。它不是固定模板库，也不是坐标系统；主控大模型根据内容选择角色和版式家族，runtime 只记录和校验结构。

## 页面角色

常用页面角色：

| page_role | 适用 | 内容密度 | 视觉重点 |
| --- | --- | --- | --- |
| `cover` | 封面 | 低 | 主题、标题层级、主视觉 |
| `agenda` | 必设目录页，可呈现流程预告、学习路线或问题主线 | 中 | 模块关系和讲述顺序 |
| `learning_objectives` | 教学目标、培训目标 | 中 | 学习产出和行动目标 |
| `section_divider` | 章节页、模块介绍页 | 低 | 阶段转换和节奏；同类页面结构一致 |
| `concept` | 概念讲解 | 中 | 定义、关键词和理解锚点 |
| `definition` | 术语定义 | 中 | 概念边界和易混点 |
| `mechanism` | 原理机制 | 中高 | 因果链、结构关系 |
| `case` | 案例 | 中 | 场景、问题、处理 |
| `process` | 流程步骤 | 中高 | 顺序、动作、节点 |
| `timeline` | 时间线 | 中 | 时间、里程碑、阶段 |
| `comparison` | 对比 | 中高 | 差异、选择、优劣 |
| `matrix` | 矩阵分析 | 高 | 维度和结论 |
| `data` | 数据页 | 中高 | 图表、关键数字、结论 |
| `table` | 表格页 | 高 | 可读表格和重点标注 |
| `evidence` | 证据页 | 中高 | 依据、来源、结论 |
| `warning` | 风险、注意事项 | 中 | 警示信息和行动边界 |
| `checklist` | 清单、操作要点 | 中 | 可执行动作 |
| `practice` | 练习、互动 | 中 | 任务、步骤、答案区 |
| `summary` | 总结 | 中 | 复盘、关键收束 |
| `closing` | 结束页 | 低 | 结论、感谢、行动号召 |
| `qa` | 问答页 | 低 | 开放交流和收尾 |

## 目录页必设

所有二创 PPT 必须包含至少一页独立目录页，页面角色为 `agenda`。无论原稿是否包含目录，阶段1都须根据二创后的实际内容重新编排目录。

目录应帮助观众理解整套 PPT 的主要内容、模块关系与展开顺序。默认安排在封面之后；需要先通过情境、故事或问题导入时，可以放在简短导入之后，并在主要内容展开前呈现。

目录形式根据主题、受众、内容结构及选定风格灵活设计，可采用编号列表、主题卡片、学习路线、问题链、流程路径、时间轴或其他清晰可读的形式。标题可以使用“目录”“今天我们聊什么”“本次学习路线”等符合场景的表达，不强制统一标题或编号样式。

目录条目提炼实际内容模块，不必逐页罗列标题。条目名称、排列顺序和层级须与正文对应，覆盖主要内容，不出现正文没有的模块、遗漏核心模块或顺序不一致。目录保持简洁，以短标题为主，必要时配简短说明。

目录计入总页数。用户指定页数时，在该范围内统筹封面、目录和正文，不因增加目录而自行扩大总页数。目录页上的标题、条目、编号及其他可见文字，均须纳入该页 `final_visible_text`。

规划审阅时检查目录是否存在、内容是否与正文对应；全稿审阅时检查实际成图是否完整、准确、清晰。缺少目录页或目录与正文不一致时，对应审阅不能通过。

## 版式家族

常用 layout_family：

- `hero_cover`：封面主视觉，标题层级清楚。
- `title_and_key_points`：标题加 3-5 个关键点。
- `two_column`：左右对照，适合概念+解释、问题+方案。
- `visual_anchor_with_notes`：一侧主视觉，一侧讲解点。
- `process_steps`：横向或纵向步骤。
- `timeline_track`：时间节点和阶段演进。
- `comparison_grid`：二到四象限比较。
- `evidence_panel`：证据、数据、来源、结论合一。
- `data_focus`：图表和关键结论优先。
- `checklist_panel`：行动清单、护理要点、操作规范。
- `case_walkthrough`：案例背景、判断、处理、复盘。
- `summary_stack`：总结要点分层收束。

## 阶段1写法

`页面规划.md` 每页必须写：

- 页面角色。
- 页面标题。
- 页面目的。
- 最终可见中文文字。
- 资料依据。
- 内容保留边界。
- 视觉意图。

页面角色不是装饰标签，它决定本页该如何组织信息：

- 课件页优先学习路径：概念、例题、练习、总结。
- 护理页优先行动路径：风险、流程、检查清单、注意事项。
- 答辩页优先论证路径：问题、方法、实验、结果、贡献。
- 创赛页优先说服路径：痛点、方案、市场、模式、进展、团队。
- 仿做升级页优先原页意图：保留原页任务，只升级视觉和层级。

## 阶段2 prompt 写法

以下字段是主控选择画面结构的规划依据，不作为字段清单直接发送给模型：

- `page_role`
- `layout_family`
- `density_budget`
- `visual_anchor`
- `final_visible_text`
- `negative_constraints`
- `acceptance_criteria`

主控将当前适用的构图、风格、空间规则和必要限制整理到现有brief或候选卡的 `image_prompt_plan`；正式prompt仅编译该计划、批准正文及一次页码规则。具体合同见 [提示词建设规范.md](提示词建设规范.md)。

`content.final_visible_text` 是唯一页面文字源。内部 `title` 和页面角色用于索引和规划，不能自动增加为画面标题；标题、章节编号等通过 `text_roles` 引用批准正文条目，不一律猜测第一条是标题。普通内容页默认只有页面标题组件，不默认生成章节标签、眉题或模块导航文字。

生成提示词的正文区只放批准原文，各条目以空行分段。用途标签不夹入正文；在正文区外以“第几段作为标题/章节编号”等排版要求引用，明确这些用途名称不出现在画面中，不另复制标题文字。

准备计划时对齐content、brief和layout中的页型；`section_divider` 与章节页别名归入章节组件，`closing`归入ending，目录、封面和结束页不套普通标题组件。组件的applies_to使用角色列表，exclude_slide_indices使用正整数页序列表；enabled=false或排除的组件不输出。字段冲突或角色无法对应时先处理具体页，不同时套入两个结构。

多个章节页使用同一具体版式骨架，章节编号、标题和短说明均引用批准文字；普通内容页继承确定的页面标题位置、字体和装饰。若项目确实需要章节标签，必须作为显式 opt-in 的独立组件处理，并能追溯到批准文字和角色绑定；否则普通页不带章节标签。组件在准备计划时解析到 `layout` 一次，编译后不重复追加原始共享片段，不用“与上一页相同”代替可执行要求。

## 重复与节奏

- 同一布局骨架连续不超过2页，除非用于刻意对比、练习或连续步骤。
- 章节页、案例页、总结页可以作为节奏断点。
- 多个章节页或模块介绍页之间不按“连续重复”视为问题；它们应像同一母版的重复使用，通过编号和标题产生差异。
- 数据、表格和矩阵页面可以密度更高，但必须保持结论锚点清晰。
- 封面风格可以更强，内页应把封面元素抽象为稳定系统，不照搬封面大图。

## 禁止事项

- 不把所有页面都做成三卡片。
- 不把所有页面都做成海报。
- 不把复杂教学或专业内容压成口号。
- 不让页面角色和实际内容不匹配。
- 不让版式变化来自随机审美，而不是内容任务。
- 不让多个模块介绍页随机换结构、换编号样式或换标题位置。
