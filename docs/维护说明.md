### 国际版 Canva 可编辑连接器

- `/canva`、`/可画` 均指国际版 Canva；当前 WorkBuddy 的可编辑路线是用户已启用并完成 OAuth 的 Canva MCP，Codex 的可编辑路线是 Canva 插件。
- `install-profile` 只切换 Skill 根入口，**不**安装连接器、不修改用户级 MCP 配置、不处理 OAuth 或 token，也不检查某个会话是否已暴露 Canva 工具。
- 每次实际编辑前由当前会话做工具/授权 preflight。WorkBuddy 缺少 `mcp__canva__*`、OAuth 失效或无设计编辑权限时，任务必须标为 connector 阻断或人工交接；不能假装改走 Codex 插件。
- Canva按本次真实授权修复转换错字、标点、字号、颜色及元素位置/尺寸，默认5页一批，回读后直接commit并核对保存结果，不再逐批确认。预览URL允许通过普通HTTP请求在内存中读取图片字节并输出图像块，或下载同一原图到项目内部再用图片工具读取，无需额外下载授权；禁止使用Computer Use读取、截图或浏览器控制。实际审阅对应页和编辑状态的图片后才记录视觉结果；可用读取方式均无法实际查看时记录readback_only/verified=false，继续有明确参考和对象依据的工作，不冒称视觉通过。没有工具能力或已发现错误仍明确处理，Magic Layers及页面重建不自动授权。
- token、签名导出 URL、签名缩略图 URL、本机路径都不得写入 task 记录、日志、发布包或变更记录。

## 维护原则

1.3.0保留原三步业务流程、授权、正文、正式中转模型、试样范围、Canva5页及全部点击状态质量门槛。新增资源协调、可靠返回恢复、独立候选继承、真实文档排版门禁和全流程计量，参考《并发与全流程计量规范》《首轮生图与返工规范》《文档后台全页验收规范》。安装/更新前先收口运行任务，不能替换正在使用的共享代码。后台Word/PowerPoint实测与结构/多进程模拟分开记录；不以模拟API证明实际生图质量或服务额度。

生图并发严格保留原规则：每个batch/run独立最多6个并发，多个独立批次或窗口不共享额度、不设置全局生图互斥、账号许可池或共享限流退避。项目写入/同项目同图去重/Canva设计/Office后台保护不能用来限制无关生图请求；Office仍只使用后台方式。

- 正式生图固定为 `openai_image_api` / `gpt-image-2.5`；不可用时停止并报告，不启用其他分组、模型、中转站或内置工具作为备用。不得新增模型覆盖或自动切换机制；历史其他模型记录保留事实，不改写已有项目产物。
- 不把测试、输入、输出、过程文档塞进普通用户发布包。
- 不恢复旧的文件整理类用户快捷入口。
- 不恢复已删除的用户说明文件。
- 不新增一套和 `PPT一致性.md`、`图片风格.md` 平行的风格权威。
- 本次不维护旧项目兼容；旧资料可作为新项目源输入，不自动迁移旧状态。
- Runtime 只做确定性检查，主控大模型保留审美、教学质量、内容取舍和返工判断。

## 常见故障

- 根目录同时出现 `AGENTS.md` 和 `CODEBUDDY.md`：运行 `install-profile --target codex` 或 `install-profile --target workbuddy`。
- 新项目跑到 `.skill/` 内：检查是否使用了旧命令或旧 cwd，正确命令以 `python3 .skill/scripts/pptctl.py` 开头。
- 新项目跑到 `outputs/projects/`：检查是否显式传入旧 `--output-root`，默认输出应为 `PPT输出/`。
- 旧项目状态：不自动迁移。需要当前新流程时建立新项目并登记原资料。
- `输入资料/` 或 `PPT输出/` 下产物出现在 Git 状态里：重新运行当前 profile 安装命令，同步 `.git/info/exclude`。
- 中文 PDF 缺字：检查系统中文字体，必要时设置 `PPT_SKILL_CJK_FONT`。
